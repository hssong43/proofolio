# proofolio

> **2026-09-20 v0.16 품질 개선:** 근거 단독 판독 → 역할·맥락 묶음 → 전체 카드 전제 검사 → 문항 다양성 순서로 수정했다. 두 PDF의 기존 추출을 고정한 유료 부분 재생에서 디자인 **자동 10개/별도 적합 4개**, 마케팅 **자동 5개/별도 적합 3개**. 후속 필터의 무과금 재검사는 4개/3개를 남겼지만 새 전체 실행 결과는 아니다. 핵심 포인트 누락이 남아 **최소 MVP 품질·안전한 10문항은 미달**이다. [단계별 판단·실제 비용](benchmark/QUALITY_IMPROVEMENT_REPORT.md).

> **마지막 전체 웹 시험은 v0.15:** 디자인 자동 7개/별도 적합 2개, 답변 7개 로컬 저장 통과. 마케팅은 스캔 중 429로 실패했다. 이후 429 대기 재시도·같은 모델의 적격 공급자 fallback을 구현했다. v0.16의 14회 유료 호출은 모두 성공했지만 429가 없었으므로 실제 복구 효과는 미확인이다. [웹 이력](benchmark/TEN_QUESTION_WEB_REPORT.md) · [재개 위치](CHECKPOINT.md).

포트폴리오 PDF를 읽고 **제출물의 근거를 연결한 질문**을 만드는 로컬 MVP.
Node.js 24 + TypeScript 코어 **0.16.0**, 결과 스키마 **0.16**, Next.js UI(PR #1)를 함께 사용한다.
디자인·마케팅만 지원하며 실제 저자·성과의 진위, 지원자의 신뢰도·채용 합불은 판정하지 않는다.

## 현재 구성

실행 경로는 하나다.

`웹 또는 CLI → OpenRouter Gemini 비전 → 검증 근거 JSON → OpenRouter Claude Opus 질문 → Gemini 원본 대조`

- UI: 직무 선택 → PDF 업로드 → 분석 진행 → 근거가 연결된 질문 → 답변 작성·로컬 저장.
- 모델: 스캔 `google/gemini-3.8-flash`, 시각 추출·검수 `google/gemini-3.1-pro-preview`, 질문 `anthropic/claude-opus-5`.
- 분석 기본값: 최대 5페이지·3개 검증 포인트·2개 프로젝트·10문항. 필수 맥락 페이지가 예산에 맞지 않으면 포인트 전체를 보류한다.
- 웹·API·CLI·코어의 문항 수 계약은 `src/constants.ts`의 10으로 통일한다. 범위는 1~10이며 근거가 부족하면 적게 반환한다. 생성은 최대 2라운드이고 세 문항에서 품질 조건을 충족해도 조기 종료하지 않는다.
- Gemini Developer API, Files API, 직접 GCP/ADC 클라이언트와 이전 유료 재개·질문 재실행 스크립트는 제거했다. Gemini **모델**은 OpenRouter를 통해 계속 사용한다.
- 과거 PDF·결과·질문·비용 원장·검증 보고서는 보존한다. 과거 보고서의 실행 명령과 가격은 당시 기록이며 현재 실행 경로가 아니다.

## 설치·환경 설정

```sh
node --version                 # 24.x
npm ci
npm ci --prefix web
cp -n .env.example .env        # 기존 .env는 덮어쓰지 않는다
```

[.env.example](.env.example)을 참고해 **루트** `.env`에 `OPENROUTER_API_KEY`를 설정한다.
기존 `.env.openrouter`도 읽는다. 우선순위는 프로세스 환경변수 → `.env` → `.env.openrouter`다.
Gemini API 키·Google ADC는 필요하지 않으며 레거시 자격증명은 로더가 읽지 않는다.
실제 키·원본 PDF·실행 결과는 Git에 포함하지 않는다. `NEXT_PUBLIC_` 변수에 키를 넣지 않는다.

`PROOFOLIO_MAX_COST_USD=0`은 **유료 실행 금지**다. 웹에서 실제 분석할 때만 승인된 누적 한도(0 초과 10달러 이하)를 명시한다.
CLI의 `--max-cost-usd`는 같은 한도를 명시하는 대안이다. 이미 만든 원장의 최초 한도와 동일해야 한다.
`PROOFOLIO_BUDGET_LEDGER=output/openrouter-budget.jsonl`을 CLI·웹·벤치마크가 함께 사용한다.
한도 부족을 해결하려고 새 원장으로 바꾸거나 원장을 삭제하지 않는다.

무료 키·모델·가격·ZDR 확인:

```sh
npm run check:openrouter
```

이 검사는 질문 생성이나 PDF 전송을 하지 않는다. 실제 생성 시에는 리셋 없는 유한 OpenRouter 키 한도가 필요하며,
`google-vertex/global`을 우선하되, 모델별 가격·ZDR·출력 형식·용량 검사를 통과한 다른 공급 경로도 허용한다.
검사 결과의 `allowed_providers`만 요청의 `provider.only`에 넣고 `allow_fallbacks: true`를 사용한다.
`data_collection: deny`, `zdr: true`, `require_parameters: true`, 가격 상한은 유지한다. 적격 경로가 없으면 생성 전에 중단한다.
계정 수준의 공급자/개인정보 제한은 이 설정으로 우회하지 않는다. [OpenRouter 공급자 라우팅](https://openrouter.ai/docs/guides/routing/provider-selection).
키 한도는 로컬 테스트 예산이나 계정 잔액으로 취급하지 않는다.

## 웹

```sh
npm run dev                     # http://127.0.0.1:3000
npm run check:web
npm run build:web
npm --prefix web run start      # 빌드한 앱 실행, 기본 localhost 전용
```

- `?questions=1..10`: 최대 문항 수. 기본 10개이며 근거가 부족하면 더 적게 생성한다.
- `?seconds=10..120`: 질문당 답변 시간. 기본 40초.
- `?demo=1&fast=1`: **고정 목데이터**로 화면 흐름만 시연한다. PDF 분석 성능 검증이 아니다.
- 개발 서버에서 macOS 파일 감시 한도 `EMFILE`이 나타나면 `WATCHPACK_POLLING=1000 npm run dev` 또는 빌드 후 `start`를 사용한다.
- 질문·인용문은 줄바꿈까지 보존하며 페이지 번호는 코어가 검증한 앵커에서 가져온다.
- 답변은 `output/web/runs/<runId>/answers.json`에 로컬 저장한다. 기업 전송·답변 평가 기능은 없다.
- 부분 결과는 목표/생성 개수와 제한 사항을 표시한 뒤 진행할 수 있다. 질문이 없으면 시작하지 않는다.
- 답변 작성 완료와 서버 저장 완료를 구분한다. 실패 시 현재 화면의 답변을 유지해 저장만 재시도한다. 새로고침/탭 종료 뒤 복구 기능은 없다.
- 답변 API는 완료된 실행의 질문 ID·중복·문자열 길이·경과 시간을 검사한다. 동일 재전송은 허용하지만 이미 저장된 다른 답변은 덮어쓰지 않는다.
- `raw/` 원본 모델 응답, `regions/` 영역 미리보기, 결과·이벤트·답변은 해당 실행 폴더에 보관하며 Git에는 포함하지 않는다.

현재는 **로컬 단일 Node 프로세스 MVP**다. 로그인·접근 권한·보존 기간·작업 큐·여러 서버 간 상태 공유가 없으므로 그대로 인터넷에 공개하거나 서버리스에 배포하지 않는다.
진행 파일은 원자적으로 교체하고 기록을 순서대로 처리하며, 예산 원장 잠금으로 중복 지출을 막는다.

## CLI·현재 벤치마크

승인된 누적 한도를 넣고 항상 새로운 출력 경로를 사용한다.

```sh
npm run analyze -- example.pdf --track design --max-cost-usd 10 \
  --output result.json --guide-output questions.txt --events \
  --raw-response-dir new-raw --preview-dir new-regions

# 기존 두 문서 검증 경로. 아래는 실행 예시이며 자동 실행하지 않는다.
npm run benchmark -- run --phase pilot --run UNIQUE_RUN \
  --ids d-shuu,m-damyul --max-cost-usd 10
npm run benchmark -- report --run UNIQUE_RUN
```

`analyze:openrouter`는 같은 CLI의 호환 별칭이다. `--provider gemini`/GCP 옵션은 거부한다.
벤치마크 신규 실행은 현재 두 PDF pilot만 지원한다. 과거 결과의 읽기 전용 보고서·비교 집계는 유지한다.
다운로드한 원본 PDF는 재배포하지 않으므로 별도 준비한 로컬 자료가 필요하다.

근거/질문 단계만 좁혀 시험할 때는 기존 코어를 재사용하는 명시적 유료 명령이 있다. 같은 두 PDF만 지원하며 기본 `npm test`에서는 실행하지 않는다.

```sh
npm run test:quality:paid -- --paid --input PRIOR_RESULT.json \
  --id d-shuu --run NEW_SOURCE_RUN --stage sources --max-cost-usd 10
npm run test:quality:paid -- --paid \
  --input output/benchmark/quality-replays/NEW_SOURCE_RUN/result.json \
  --id d-shuu --run NEW_QUESTION_RUN --stage questions --max-cost-usd 10
```

선정·추출은 입력 결과대로 고정한다. 질문 재생에는 v0.16 독립 판독을 마친 근거만 허용한다. `--question-max-output-tokens`는 재생 실험에 한해 출력 상한을 낮출 수 있고 manifest에 기록한다(기본 16,384). 위 명령도 잔여 최대 비용 예약이 부족하면 차단되며 기존 유보금/원장을 우회하지 않는다.

## 분석 방법·안전장치

1. PDF 형식·암호화·50 MB·1~60페이지 제한을 확인한다.
2. 문서가 길면 겹치는 청크로 목차를 읽고, 분리 PDF 페이지 번호를 원본 번호로 변환한다.
3. 프로젝트와 검증 포인트를 선정하고 중심 페이지와 필수 맥락을 함께 선택한다.
4. 페이지/타일 이미지에서 작업물·설명문·제목·차트·참고자료를 구분한다. 제목 box에 바깥 설명문을 섞거나 배치만으로 협업·전후 관계를 확정하지 않는다.
5. 디자인은 역할·선택·수정 과정·사용/검증, 마케팅은 지표명·값·단위·기간·분모·비교 기준을 분리한다. `metric_sources`의 필드별 앵커에만 원문을 대조하고 없는 조건은 `null`로 둔다.
6. 인용문·영역·숫자 대상·필수 맥락을 검사한 뒤 Gemini에 **기존 설명 없이 연결 크롭과 ID만** 제공해 문자/시각 관찰을 읽는다(`CropReadings`). 그 판독과 근거 후보를 별도로 대조하고, `reading_excerpt`가 자기 영역 원문/관찰에 속하는지 확인한다. `source_check.anchor_checks`가 누락·불확실·불일치이면 해당 근거는 질문에 쓰지 않는다. 텍스트 레이어 부재를 이미지 속 원문 부재로 해석하지 않는다.
7. Opus에는 선택된 검증 구절·관찰과 `context_bundle`을 전달한다. 필수 맥락 앵커 누락을 거부하고 원문에 없는 역할은 다른 이미지/프로젝트에서 가져오지 않는다. Gemini가 자기 출처 크롭으로 본문·의도·각 가이드를 따로 검사한다. `premise_checks`는 전제별 출처, `field_text`는 검사한 실제 문구, `experience_check`는 현재 해석/행동 자체의 조건부/명시 행동/근거 없음 구분이다. 미기재 수행 이력·모집단을 가이드에 넣는 것도 오류다. 로컬 출처 대조와 알려진 표현 회귀를 함께 적용하지만 일반 의미 정확도를 보장하지는 않는다. 같은 근거라도 실제 다른 답을 요구할 때만 재사용하며 중복·반복 참여 질문을 제외한다.
8. 최대 두 생성 라운드에서 요청 개수 달성 또는 빈 후보 응답이면 종료한다. `question_target`에 요청·생성·부족 수를 남기며 부족한 질문을 템플릿으로 채우거나 분석 페이지를 자동 확대하지 않는다.

글자 없는 명확한 작업물은 텍스트 판독 불가만으로 제외하지 않는다. 텍스트 인용에는 판독 검사를 유지하고, 시각 객체에는 명확한 식별과 크롭 대조를 요구한다. 마케팅 대시보드의 독립된 수치 행과 바로 다음 지표명은 온전한 값으로 대조하며, 단위·부호·수량 대상·범위를 잘라낸 인용은 계속 거부한다. 도시/성별/연령 같은 분류 축을 분모로 넣지 않는다.

독립 판독에도 누락이 있으며 잘못된 맥락 하나 때문에 정상 사실까지 제외되는 한계가 있다. 빈 프로젝트 추출은 원인 이벤트를 남기지만 자동 성공으로 보완하지 않는다. 스키마 0.15 이하 저장 결과는 그대로 보존하며 새 필드가 없다고 새 검사를 통과한 것으로 소급 해석하지 않는다. 제출물에 주장이 보인다는 것과 실제 저작·성과가 증명됐다는 것은 별개다.

- 형식 오류는 최대 1회 재시도한다. 이와 별도로 각 요청의 명시적 429(HTTP 오류 또는 HTTP 200 본문 내부 오류)는 기본 30초·60초 대기로 최대 2회 재시도한다. `Retry-After`가 더 길면 해당 대기를 지키고, 120초 초과면 조기 재전송하지 않고 중단한다. 일반 네트워크/502 오류는 재시도하지 않는다. [OpenRouter Retry-After](https://openrouter.ai/docs/api_reference/errors-and-debugging#retry-after-header).
- **실패 요청의 실제 사용량·비용을 정산할 수 있어야 재시도한다.** 미확인 비용은 0원 처리하거나 유보를 자동 해제하지 않는다. 각 재시도 전에 키 잔여 한도·공유 예산을 다시 확인하고 별도 예약한다. 원본 응답의 `_application_http_attempt`, 사용량 행의 시도·대기 기록과 보고서의 `application_http_retries`로 실제 재시도 수를 남긴다. 공급자 내부 재시도 수는 계속 미확인이다.
- 세션의 유료 요청 시작 간격은 16초다. 직렬 스캔 중 관측한 상위 429를 완화하기 위한 조치이며 공식 분당 한도나 장애 해결 보장은 아니다. 대기는 비용 예약 전에 하며 취소할 수 있다.
- HTTP 오류는 안전한 공급자/오류 코드와 request/generation ID를 보존한다. 원문을 포함할 수 있는 중첩 오류 메시지는 저장하지 않는다. 과거 502에서 버려진 상세 정보를 소급 복구할 수는 없다.
- 호출 전 최대 컨텍스트·출력 비용을 보수 예약한다. 이것을 실제 입력 토큰 사용량으로 보고하지 않는다.
- API가 보고한 입력·출력·추론 토큰과 비용을 기록한다. 추론은 출력에 포함돼 중복 합산하지 않으며 미확인 값은 추정하지 않는다.
- 비용 미확인·잔액 부족·가격/모델 조건 변경은 이후 호출을 막는다. 과거 미확인 유보금은 승인된 기록 그대로 유지한다.
- JSON/Zod 통과 및 동일 모델 재검수는 독립적인 정확도 증명이 아니다.

## 검증 상태

schema 0.16 구현, **137/137 코어 테스트·양쪽 타입 검사·diff 검사 통과**. 기존 검사를 유지하고 크롭 단독 판독, 잘못된/누락된 판독 구절, 필수 맥락, 필드별 수행 이력/모집단, 정상 선택 이유의 과잉 제외 회귀를 추가했다. 이번에는 프로덕션 빌드·Playwright·실제 웹 저장을 재실행하지 않았다. v0.15의 build·Playwright 10/10은 이전 실행의 검증이다.

최신 유료 실험은 기존 추출을 고정한 근거 재검수·질문 재생이며 스캔/추출부터 시작한 테스트가 아니다. 디자인은 후보 11개→자동 10개→별도 적합 4개, 마케팅은 후보 11개→자동 5개→별도 적합 3개였다. 두 분야 모두 잘못된 연결은 0건이었지만 추가 전제가 각각 6건/2건 남았다. 검수자는 Codex이며 사람 전문가가 아니다.

그 오류를 반영한 최신 필터로 저장 카드를 그대로 검사하면 4개/3개가 남고 알려진 잘못된 통과는 0건이다. 이는 같은 개발 사례의 **무과금 사후 검사**로, 새 자동 생성/독립 평가셋 성공이 아니다. 원본 결과와 제외 후보는 수정하지 않았다. 디자인 유학 가이드와 마케팅 나머지 포인트의 근거 부족도 남아 있다.

| 분야 | 자동 최종 질문 | 별도 원문 검수 통과 | 근거 재검수+질문 시간 | 해당 부분의 실제 API 비용 |
| --- | ---: | ---: | ---: | ---: |
| 디자인 (`quality-d-*`) | 10 | 4 | 356.027초 | $0.557102 |
| 마케팅 (`quality-m-*`) | 5 | 3 | 205.228초 | $0.361059 |

합계 실제 입력 171,987 / 출력(추론 포함) 32,585 / 그중 추론 5,865 토큰, 14호출 **$0.918161**다. 형식/애플리케이션 HTTP 재시도 0, 공급자 내부 재시도 미확인. 디자인/마케팅은 실행 사이 코드와 출력 상한이 달라 동등 A/B가 아니며 부분 비용을 전체 PDF 비용과 직접 비교하지 않는다. [세부 결과](benchmark/QUALITY_IMPROVEMENT_REPORT.md).

공유 원장 누적 확인 비용 **$3.37881625**, 과거 미확인 유보 **$1.634304** 불변, 잔여 **$4.98687975**, 활성 예약 0·차단/잠금 없음. 다음 Opus 입력 최대 컨텍스트 예약만 $5여서 현재 정책으로는 새 유료 질문 호출이 막힌다. 실제 $10 소진이나 계정 잔액 부족은 아니며 새 원장/유보 해제로 우회하지 않았다.

마지막 전체 웹 결과는 [별도 이력](benchmark/TEN_QUESTION_WEB_REPORT.md)에 있다. 당시 디자인 7개 답변 저장은 통과했지만 품질은 2개 적합, 마케팅은 생성 전 429로 미완료다. **최소 MVP·10문항 목표는 여전히 미달**이며 20개 전체나 모델 일반 성능으로 확대하지 않는다. 원본/이전 결과/원장은 보존했고 커밋·푸시·병합하지 않았다.

```sh
npm run check
npm test
npm run check:web
npm run build:web
npm run test:e2e                 # Chromium 데스크톱 + 모바일, 유료 호출 없음
```

현재 회귀 테스트는 기존 근거·질문·PDF 좌표 검증과 OpenRouter 비용 안전장치, UI 어댑터·실행 인자 검사를 포함한다.
삭제한 직접 Gemini/GCP 전송 경로 전용 테스트는 제거했으며 새 UI 테스트로 대체했다.
저장된 두 문서 결과를 UI에 연결하는 검사는 새 질문 생성이나 새로운 품질 합격으로 집계하지 않는다.

기존 무료 UI 검사는 1440×1000/390×844에서 합성 10문항 전체 답변, 부분 결과 경고, 0문항/분석 실패 차단, 저장 지연·실패·답변만 재시도를 다룬다. 실제 로컬 파일 저장과 동일/동시 재전송은 별도 합성 완료 실행으로 현재 코어 테스트에서 검사했다. 실제 디자인 7개 답변 저장은 이전 v0.15 웹 시험 기록이며 v0.16 웹 검증으로 소급 집계하지 않는다.

### 반복 가능한 Playwright 검사

```sh
npm ci --prefix web
npm --prefix web exec -- playwright install chromium   # 최초 한 번
npm run test:e2e
```

`web/`에 Playwright Test 1.63.0을 고정했다. [공식 테스트 서버 설정](https://playwright.dev/docs/test-webserver)을 사용해
프로덕션 빌드 후 `127.0.0.1:3101`에서 전용 서버를 시작하고 종료한다. 같은 `.next`를 사용하므로 실행 중인 웹 개발/미리보기 서버는 먼저 중지한다.
기존 서버를 재사용하지 않으며 키는 빈 값, 승인 예산은 0으로 고정한다. 외부 Browser 플러그인이 없어 Playwright를 직접 사용했다.

- 두 직군 × 데스크톱/모바일: 업로드 → running/complete 폴링 → 다중행 질문/인용문/페이지 표시 → 모든 답변 전송 → 완료.
- 실제 API 방어: 11문항/짧은 PDF 400, 예산 0 차단 500, 외부 Origin 403.
- 정상 흐름의 콘솔 오류/경고·가로 넘침·오류 오버레이를 검사한다. 분석 응답/답변 저장은 **합성 데이터와 API stub**이므로 모델 품질·실제 PDF 분석·실제 디스크 저장의 E2E 증거가 아니다.
- 스크린샷/실패 trace는 OS 임시 폴더의 `proofolio-playwright-results/`에만 저장한다. 원본 포트폴리오나 비밀키 없이 재실행할 수 있다.

2026-09-20 **v0.15 당시**: **10/10 UI 테스트**, **123/123 코어 테스트**, 양쪽 타입 검사와 프로덕션 빌드 통과. 첫 샌드박스 실행은 Chromium macOS MachPort 권한에서 앱 진입 전 실패했고, 승인된 환경의 재실행과 최종 재검사는 통과했다. 이전 중복 `.next` 선언 오류도 정상 빌드로 생성 캐시를 갱신한 뒤 해소됐으며 소스 파일은 삭제하지 않았다.
실행기 자체의 `NO_COLOR`/`FORCE_COLOR` 충돌 경고는 있었지만 정상 흐름의 브라우저 콘솔 오류/경고는 없었다.

### 명시적 유료 웹 E2E (기본 테스트와 분리)

두 원본 PDF가 로컬에 있고 별도 실행 승인이 있을 때만 실행한다. 디자인 데스크톱·마케팅 모바일에서 각각 한 번 업로드한다. 기본 무과금 명령에는 이 테스트가 포함되지 않는다.

```sh
PROOFOLIO_PAID_E2E=1 PROOFOLIO_MAX_COST_USD=10 PROOFOLIO_E2E_RUN=NEW_UNIQUE_RUN_ID \
  npm run test:e2e:paid
```

- `127.0.0.1:3102` 전용 서버, worker 1·자동 재시도 0. 실패 후 자동 재업로드하지 않는다.
- 실행 ID는 소문자 영문·숫자·하이픈만 사용한다. `web-ten-01`~`web-ten-05`는 사용 완료 경로이며 덮어쓰지 않는다. `PROOFOLIO_E2E_DOCUMENT=d-shuu` 또는 `m-damyul`은 별도 승인한 단일 문서 시험에만 사용한다. 미설정 시 두 문서이며 마케팅부터 진행한다. 실패 후 자동 재업로드하지 않는다.
- 코드/프롬프트/웹/모델 설정/PDF 해시, 무료 모델·공급자·가격·ZDR 검사, 기존 원장 전후 상태를 고정·기록한다.
- 기존 `output/openrouter-budget.jsonl`만 사용한다. 현재 $1.634304 미확인 유보를 전액 유지하고 새 원장이나 해제로 우회하지 않는다. 이 유보는 실제 지출액이 아니다.
- 실제 웹 실행 결과를 `output/benchmark/runs/<run>/` 보고서 입력으로 복사한다. 별도 CLI 유료 재분석은 하지 않는다. 답변은 명확히 표시된 **자동 E2E 합성 답변**이며 후보자 답변 평가가 아니다.
- 원문과 전체 카드를 별도로 검수해 `source-audit.json`을 작성한 후 `npm run benchmark -- report --run <run>`으로 기존 집계기를 재사용한다.
- 최소 MVP(문서별 3개·설명 질문 2개·핵심 포인트 충족·추가 전제/오연결 0)와 **10문항 목표**는 별도로 보고한다.
- 종료하면 유료 서버가 닫힌다. 미리보기는 `OPENROUTER_API_KEY= PROOFOLIO_MAX_COST_USD=0 npm --prefix web run start -- --port 3100`으로 복귀한다.

## 다음 단계 — MVP 완료 순서

1. **근거 정확도·정상 근거 회복.** 단독 크롭 판독은 유지한다. 독립 사실의 추출 단위를 나눠 잘못된 맥락 한 개에 정상 작업물이 함께 버려지지 않게 하고, 작은 시각 요소 누락·줄바꿈 오탐·빈 프로젝트 추출을 평가한다. 이미 실패한 묶음에서 앵커를 임의 삭제해 통과시키지는 않는다.
2. **역할·맥락을 원문 범위대로 연결.** 현재 묶음의 필수 앵커 검사를 유지하고 실제 역할 문구와 작업물의 연결을 회복한다. 다른 근거/프로젝트의 역할을 추정해 빌리지 않는다.
3. **전체 카드 전제 관리.** 같은 필드에서 행동 자체를 조건화하고, 가이드에 없는 수행 이력·모집단·결과를 요구하지 않는다. 알려진 표현 가드는 유지하되 정상 질문의 오탐도 함께 검사한다. 저장된 개발 카드의 필터 성공과 새 생성 성능을 구분한다.
4. **다양성·10문항은 그 다음.** 실제 다른 작업물/답변 과제와 선정 핵심 누락을 검사한다. 안전한 3개·설명 2개·핵심 포함·카드 오류 0을 먼저 입증하고 10개는 별도 목표로 보고한다. 추가 유료 실행은 최대 비용 예약 조건을 충족해야 한다.

이후 검증된 범위로 로컬 시연을 고정한다. 로그인·Supabase·음성·답변 평가·20개 확장은 제외한다. 공개 배포 전 인증/접근 권한/보존 정책/작업 실행 방식과 의존성 보안은 별도 처리한다.

설치 시 `npm audit`는 기존 Next.js → PostCSS 경로의 취약 의존성 **2개(높음 1·중간 1)**를 보고했다.
Playwright에서 발생한 항목은 아니며 자동 수정 가능 버전이 표시되지 않아 이번에 강제 업데이트하지 않았다. 공개 배포 전 재점검/패치가 필요하다.
