# 질문 품질 개선 검증 — 2026-09-20 / v0.16

## 결론

**근거 정확도 → 역할·맥락 묶음 → 질문·가이드 전제 → 다양성·개수** 순서로 수정했다. 같은 두 개발용 PDF의 기존 추출 결과를 고정하고, 근거 재판독 2건과 질문 생성·검수 2건을 유료 실행했다. 전체 PDF 재분석이나 웹 E2E는 아니다.

| 분야 | 재검수 전 → 후 적격 근거 | 새 후보 | 당시 자동 최종 | 별도 원문 검수 통과 | 최신 필터의 무과금 재검사 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 디자인 | 5 → 2 | 11 (7+4) | 10 | 4 (q3/q5/q8/q10) | 10 → 4 |
| 마케팅 | 2 → 1 | 11 (5+6) | 5 | 3 (q2/q3/q5) | 5 → 3 |

검수자는 **Codex이며 사람 전문가가 아니다.** 연결 원본 페이지·정확한 크롭과 모든 최종 카드의 본문·의도·가이드를 대조했다. 같은 Gemini의 승인만으로 정확도를 인정하지 않았다. 카드 원문, 자동 결과, 제외 후보를 수정하거나 삭제하지 않았다.

두 분야 모두 질문 수 하위 조건(근거 있는 3개 이상·설명 질문 2개 이상)은 만족하지만, **당시 자동 최종 카드에 오류가 남고 선정 핵심 포인트가 빠져 최소 MVP 품질은 미달**이다. 디자인의 자동 10개를 ‘쓸 만한 10개’로 집계하지 않는다. 새 필터의 4개/3개는 저장된 동일 개발 사례의 사후 검증이며, 최신 코드 전체를 유료 재실행한 결과나 미사용 평가셋 성능이 아니다.

## 단계별 변경·관측·판단

### 1. 근거 정확도: 기존 설명을 보여주지 않는 크롭 판독

- Gemini에 영역 ID와 정확한 크롭만 먼저 보내 `CropReadings`의 문자·시각 관찰을 얻는다. 기존 추출 설명·질문·프로젝트 가설을 주지 않는다. 같은 영역 판독은 해당 프로젝트 내에서 재사용한다.
- 다음 호출은 원본 후보와 이 판독을 텍스트로 대조한다. `reading_excerpt`는 자기 영역의 원문 또는 관찰이어야 한다. 다른 영역, 누락, 불확실 판독은 통과하지 못한다. 통과 시 질문 입력의 시각 설명도 새 판독 구절로 제한한다.
- **개선 확인:** 디자인 중앙 포스터 크롭에 전체 사진의 배경 설명을 붙였던 오류를 차단했다. 마케팅 도시 분류 축을 분모로 넣은 기존 근거는 현행 로컬 지표 검사에서 제외했다.
- **남은 오탐:** 디자인 포스터의 작은 포토카드 미리보기는 실제 있지만 첫 판독이 빠뜨렸다. 또 역할 문구는 크롭에 있지만 줄바꿈 때문에 검수 모델이 거부했다. 잘못된 맥락 앵커 하나 때문에 같은 묶음의 정상 문구까지 잃는 사례도 있다. 정확한 영역을 줬다고 이미지 인식이 확실해지는 것은 아니다.
- 후속 코드에 공백 정규화 `text_literal_match` 힌트, 판독 누락을 부재로 확정하지 않는 지시를 넣었다. **그 디자인 오탐을 유료 재실행해 회복했는지는 미확인**이다. unsupported를 수동 supported로 바꾸지 않았다.

**판단:** 이 분리는 유지하되, 다음 우선순위는 정상 근거 보존이다. 추출 시 독립 사실을 나누고 각 사실에 정말 필요한 맥락만 묶어야 한다. 실패 앵커를 사후 삭제해서 통과시키거나 박스를 임의로 넓히는 방식은 쓰지 않는다. 같은 Gemini의 별도 호출은 외부 독립 검증이 아니다.

### 2. 역할·맥락: 동일 근거 안의 필수 연결을 고정

- `context_bundle`에 필수 맥락 앵커, 원문과 직접 대조한 세부 사실, 알 수 없는 필드를 제공한다. 맥락 앵커를 빼고 작업물만 선택한 질문은 유료 검수 전에 거부한다.
- 최초 영역 분류의 `source_role`과 전체 `crop_reading`은 작가 모델에 전달하지 않는다. 확인한 구절·관찰만 사용하고 다른 이미지/프로젝트의 역할을 가져오지 않는다. `authorship_verified=false`는 문서 기재와 실제 저자 확인이 다르다는 뜻이다.
- 이번 구현은 **한 근거 묶음 안의 연결 보존**이다. 서로 다른 근거 ID에서 역할을 자동 병합하는 새 시스템은 만들지 않았다.
- 디자인 유학 가이드 프로젝트는 기존 추출이 처음부터 비어 있어 이번 재생에서도 근거가 없다. 빈 추출 이벤트에 모델의 빈 응답인지 로컬 전부 제외인지 기록하도록 했고, 읽기 어려운 본문과 보이는 작업물을 구분하도록 지시했다. **새 추출을 유료 실행하지 않아 회복은 미입증**이다.

**판단:** 현재 설명 가능한 질문이 특정 작업물에 몰리는 주원인은 작가의 질문 능력만이 아니라 전달되는 근거의 좁은 범위다. 원문에 적힌 역할과 작업물 연결을 먼저 회복하고, 기록되지 않은 참여는 조건부로 확인해야 한다.

### 3. 질문·가이드: 각 필드의 사실 전제를 별도로 검사

- `field_checks`에 검사한 `field_text` 전체와 `experience_check`를 기록한다. `observed`(현재 해석), `conditional`(행동 자체가 조건부), `documented`(행동 원문), `unsupported`를 구분한다. 조건문은 같은 필드에 있어야 하고, 행동 근거는 해당 텍스트 앵커와 대조한다.
- 디자인 자동 10개 중 6개는 개인의 선택/적용/수정 이력을 미기재 상태에서 전제했다. ‘기준이 있었다면’은 ‘실제로 적용했다’는 전제까지 조건화하지 않는다. 가이드에만 주의 문구가 있어도 본문의 전제는 해결되지 않는다.
- 마케팅 자동 5개 중 2개는 가이드에 없는 모집단을 넣거나, 현재 자료 해석 대신 과거에 실제로 특정 이용자 반응을 해석했다고 전제했다.
- 반대로 원문에 이미 명시된 선택의 이유를 묻는 정상 후보를 분류 오류로 제외한 사례도 있었다. 해당 앵커에 선택 구절이 실제 있고 `premise_checks`로 연결된 경우와, 조건부 확인을 설명하는 의도 문구의 오탐을 합성 회귀로 수정했다. 제외 후보를 최종 카드로 수동 승격하지 않았다.
- 최신 무과금 재검사: 디자인의 알려진 잘못된 통과 **6→0**, 마케팅 **2→0**, 별도 검수 적합 카드의 추가 손실 **각 0**. `field-replay-v2.json`에 원본 결과 해시·코드 해시·카드별 이유를 저장했다.

**판단:** 필드별 전제 검사는 유지한다. 다만 현재 로컬 표현 검사는 알려진 오류를 잡는 유한한 회귀 가드이며 한국어 의미 판별기가 아니다. 구절만 다르게 쓰면 같은 오류를 놓칠 수 있다. 알려진 8개를 막은 사실을 일반 오류율 0으로 확대하지 않는다. 다음에는 본문뿐 아니라 가이드가 ‘확인할 설명’만 요구하는지 먼저 평가하고, 정상 질문의 탈락률도 함께 측정해야 한다.

### 4. 다양성·개수: 앞 단계 통과 뒤에 측정

- 10문항 상한·최대 2라운드·중복 제외·5페이지/3포인트/2프로젝트는 유지했다. 포인트/작업물 간 분산을 먼저 시도하고, 동일 작업물은 실제 다른 답이 필요할 때만 재사용한다.
- 문서에서 확인 가능한 작업물을 좁은 focus 문구만으로 버리지 않도록 보완했다. 이것이 원래 포인트의 모든 핵심을 충족했다는 뜻은 아니다.
- 디자인 최종은 색상/포토카드에 집중했고, 마케팅 최종은 한 채널 운영 문구에 의존했다. 두 문서 모두 선정 포인트 누락이 남았다. 최초 coverage 정의를 모델이 좁히는 문제도 남아 별도 검수에서 불완전으로 판단했다.

**판단:** 10개 강제 채우기는 보류한다. 정상 근거와 역할 연결을 회복한 뒤 작업물/설명 과제별 중복을 검사해야 한다. 같은 두 개발 문서의 수치가 좋아져도 20개 문서나 모델 일반 성능을 뜻하지 않는다.

- 형식 재시도 **0**, 애플리케이션 HTTP 재시도 **0**. 공급자 내부 재시도는 **미확인(null)**이다. 두 질문 실행은 각 2생성 라운드이며, 두 번째 생성 라운드를 오류 재시도로 세지 않는다. 429가 발생하지 않았으므로 실제 재시도/대체 경로 복구는 입증하지 못했다.
- 디자인 근거 재검수+질문 비용 $0.557102 / 별도 적합 4개 = **$0.13927550/문항**. 마케팅 $0.361059 / 3개 = **$0.12035300/문항**. **이번 부분 재생 비용만** 나눈 값이며 최초 PDF 스캔·추출 비용은 포함하지 않는다. 질문 생성·검수만 계산하면 각각 $0.11299400, 약 $0.11310367이다.
- 이전 디자인 전체 웹 시험은 자동 7개/별도 2개, 전체 비용 $0.72493675였다. 이번 자동 10개/별도 4개와 비교할 수는 있지만, 부분 재생 범위·코드·근거·질문이 달라 동일 조건의 품질 향상률이나 전체 분석 비용 절감률로 해석하지 않는다. 마케팅 직전 웹은 생성 전 429, 그 이전 사용 가능한 결과는 자동 2개/별도 0개다.
- 이번 모델은 OpenRouter Gemini 3.1 Pro Preview 근거/검수와 Claude Opus 5 질문이다. 스캔은 재실행하지 않았다. 디자인 질문 출력 상한 16,384, 마케팅은 예약 여유를 확인해 **4,096**으로 명시 실행했다. 마케팅 두 응답 모두 `stop`으로 끝나 출력 잘림은 없었다. 운영 기본 상한은 바꾸지 않았다. 코드/프롬프트 수정은 실행 사이에 이루어졌으며 각 실행 중에는 해시를 고정했다. 단일 변수 A/B가 아니다.
