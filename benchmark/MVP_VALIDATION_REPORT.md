# v0.17 MVP 개선·재검증 기록

2026-09-20. 기존 한국어 디자인 `d-shuu`와 마케팅 `m-damyul` 두 문서만 사용한다. 검수자는 **Codex이며 사람 전문가가 아니다**. 수정하지 않은 최종 카드의 본문·의도·답변 가이드를 원본 페이지와 정확한 연결 크롭으로 별도 검사한다. 같은 Gemini의 재확인은 독립 정확도 증명이 아니다.

**최종 상태: 사용자 요청으로 유료 시험 중단. 최소 MVP와 10문항 목표 모두 미달.** 확인된 신규 지출 $2.79824875에 더해 마지막 실패 요청 비용은 미확인이다. 원장 차단을 유지하고 자동 재개하지 않는다.

## 범위와 비용 승인

- 사용자가 이 시점부터 **새 실제 지출 최대 $10**을 승인했다. 기존 정산 $3.37881625와 미확인 유보 $1.634304를 유지하고, 같은 원장에 승인 행만 추가했다. 누적 유효 한도는 $15.01312025이며 최초 원장 헤더/CLI 한도는 $10 그대로다. [승인 기록](mvp-budget-approval-20260920.json).
- 미확인 과거 비용을 $0으로 처리하거나 유보를 해제하지 않는다. 호출마다 최대 비용을 예약하고 실제 API 비용으로 정산한다. 잔여 금액이 최대 예약보다 작으면 실제 $10 소진 전에도 중단한다.
- 모델은 변경하지 않았다. OpenRouter의 Flash 일반 Vertex 경로가 비활성이고 ZDR 적격 priority 경로만 활성인 무료 사전 검사 결과를 반영해, **Flash 라우팅·예약 상한만** 입력/출력 100만 토큰당 $1.35/$6.75로 올렸다. ZDR·수집 금지·같은 모델·키 한도·공유 예산 검사는 유지한다. 과거 가격으로 기록된 비용은 재계산하지 않는다.
- 실행마다 코드·프롬프트·모델·원본 PDF 해시를 고정한다. 코드 수정 사이의 반복 실행은 통제된 모델 A/B나 독립 평가셋이 아니다. 실패 실행을 삭제하거나 성공 결과로 교체하지 않는다.

## 적용한 개선

1. 포인트별 추출/판독 불가/관련 원문 없음과 원래 응답의 근거 순번을 기록한다. 필수 맥락 페이지 앵커 누락을 구조 검사한다.
2. 추출 전에 기존 영역의 고해상도 크롭을 포인트당 최대 두 개 제공한다. 페이지·박스를 자동 확대하지 않는다. 크기/종류 기반 선택은 의미 검색이 아니므로 불필요한 영역을 고를 수 있다.
3. 독립 작업물은 검수 전에 원자적으로 나누고 필요한 텍스트 맥락은 각 항목에 보존한다. 불합격 후 문제 앵커만 삭제해 통과시키지 않는다.
4. 자기 크롭의 독립 판독과 원문을 공백/줄바꿈에 한해 정렬한다. 단위·기호·단어·순서를 고치지 않고 원본 응답과 저장 인용문도 바꾸지 않는다.
5. 답변 가이드는 실제 질문에서 물은 과제의 연속 구절로 제한한다. 숨겨진 정답·추가 과정을 가이드에 새로 넣지 못하게 한다. 질문 본문 자체의 잘못된 전제는 별도 검사가 필요하다.
6. 일반 도달을 유기적 도달로 바꾸거나 성과를 기대했다고 단정하는 알려진 오류를 회귀 검사한다. 유한한 표현 검사는 일반 의미 정확도 보장이 아니다.
7. 단색 배경 텍스트 크롭의 경계에 글자 획이 닿으면 보류한다. OCR이 아닌 보수적 픽셀 검사다. 장식으로 과잉 제외될 수 있고 비단색 배경은 이 검사만으로 판정할 수 없다. 실패 박스를 자동으로 늘리지 않는다.

## 후속 수정 — 0.17.2

- 명확한 주장 하나와 같은 페이지의 독립 작업물 앵커를 **검수 전에** 별개 근거로 분리한다. 모든 앵커·필수 맥락을 남기고, 항목 간에 걸친 세부 정보는 상속하지 않는다. 비교/전후/실험/연구/지표와 페이지를 가로지르는 자료는 임의 분리하지 않는다. 주장 존재와 시각적 뒷받침은 계속 별도 판단한다.
- 작가에게 스캔의 자유문장 주제를 보내지 않고 질문 방향 enum만 보낸다. 재생성 피드백도 검수자의 자유문장/필드 추론 대신 오류 코드만 전달한다. 원래 선정 주제는 별도 coverage 검사에 그대로 남겨 누락을 숨기지 않는다.
- 최초 텍스트 영역에 실제 배경 여백을 포함하도록 좌표 지시를 구체화하고, 영역 식별/독립 판독의 reasoning을 LOW에서 MEDIUM으로 변경했다. 이미 실패한 박스의 자동 확장이나 앵커 수정은 없다.
- 시각 추출은 큰 객체/구성과 한 가지 명확한 관찰을 우선하고, 작은 장식의 구체 명칭 나열을 제한한다. 안내 접두어 조립은 멱등 처리한다.
- 같은 angle 태그를 쓴다는 이유만으로 다른 답을 요구하는 질문까지 차단하는 임시 방식은 기존 회귀 검사가 잡아 채택하지 않았다. 같은 출처도 실제 답이 다르면 여러 질문을 지원하며, 의미 중복 검수는 계속 필요하다.

## 후속 수정 — 0.17.3

- 공용 API 스키마에 `minItems/maxItems/minimum/maximum` 전달을 시도했다. category별 details는 원래 로컬 규칙과 동일한 정확히 4개를 wire에도 명시했다. 개별 키의 지원은 [공식 Structured Output 문서](https://ai.google.dev/gemini-api/docs/structured-output)로 확인했지만, 아래 실제 공급 경로의 HTTP 400 이후 **0.17.4에서 이 wire 변경은 되돌렸다.** 문서상 키 지원이 전체 스키마의 원격 수락을 보장하지 않는다.
- 형식 재시도에는 스키마 소유 필드 경로·길이 제한·고정 규칙만 전달한다. 원문 값·미등록 필드명·임의 오류 문장은 노출하지 않는다. 지표 오류를 `metric_sources.data_source`처럼 필드별로 표시하고 한 번의 재시도 상한은 유지한다.
- 부분 실패 응답에 텍스트가 있는데 토큰이 0으로 보고되면 기존 보고서뿐 아니라 코어 metrics도 `null`로 기록한다. 확인된 실제 비용은 별도 정산하며 누락된 추론/캐시도 추정하지 않는다.
- 저장된 실패 응답을 무료 재검사해 최초 오류와 재시도 오류를 각각 올바른 필드에 귀속하는 것을 확인했다. 실패 응답 자체를 수정하거나 성공 결과로 다시 쓰지 않았다.

- 공식 [요청별 정산 조회 API](https://openrouter.ai/docs/api/api-reference/generations/get-generation)를 두 번 읽기 전용 조회했으나 모두 404였다. 이는 무과금 증거가 아니다. 기존 OpenRouter 브라우저 탭도 연결 타임아웃으로 실패해 상세 오류 본문은 확보하지 못했다.
- 이번 wire 변경과 실패의 연관은 유력한 가설이지만, 공급자의 구체적 거부 필드가 기록되지 않아 단일 원인은 확정하지 못했다. [Google Cloud 문서](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/control-generated-output)는 숫자/배열 제약을 포함한 스키마 복잡성이 400을 유발할 수 있다고 설명한다. 이 문서만으로 이번 오류 원인이 증명되지는 않는다.
- **0.17.4:** API wire는 앞서 실행됐던 기본 shape로 복귀했다. category별 정확히 4개 details, 숫자/페이지 범위, 의미 검증은 로컬에서 유지한다. 안전한 필드별 형식 오류 안내, 지표 출처 검사, 토큰 미확인 처리도 유지한다. 원격 복구와 최신 질문 품질은 재시험하지 않았다.
- 사용자가 **“유료 시험 중단하고 현재 결과 정리”**를 선택했다. 새 지출 승인/유보 전환 없이 종료했다. 신규 실패 예약 `da53b77f-ccce-4533-af1f-3f943899f8d3`의 최대 **$1.4708736**을 그대로 보존한다. `active_reserved_usd`는 미정산 원장 항목이지 실행 중 요청이 아니다.
