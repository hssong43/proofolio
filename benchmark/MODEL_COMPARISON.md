# Gemini Pro / Luna High 질문 비교

2026-09-19. **이번 6개 회귀 PDF의 첫 초안에서는 Luna High가 더 나았다. 자동 채택은 하지 않았다.**
이는 Codex의 별도 원문 이미지 검수이며, 사람 전문가 평가·일반 모델 정확도·완성된 Luna API 서비스의 성능이 아니다.

## 비교 조건

- Gemini `mvp-23` 전체 분석은 중단하거나 바꾸지 않고 6개 모두 정상 종료했다. 코어 해시 `005fc9349192bc4a74d794366870da924b08ef2585f19f5cc2e7f90e874b172a` 불변.
- Gemini 질문 모델 `gemini-3.1-pro-preview` / MEDIUM, Luna 서브에이전트 `gpt-5.6-luna` / HIGH. Luna 모델·effort는 각 전용 세션의 실제 기록으로 확인했다.
- 각 PDF의 **같은 검증 근거, 동일한 앱 질문 프롬프트·스키마, 동일 렌더링 PNG**를 전달했다. 입력/PDF/PNG/출력 해시를 저장했다. Luna가 PDF 전체를 따로 추출한 실험이 아니라, 공유 Gemini 추출 결과 뒤의 질문 작성 단계 비교다.
- 문서마다 새 Luna 컨텍스트, Gemini 질문·결과·gold 접근 금지. 작성 모델은 상대 출력을 보지 않았지만 최종 Codex 검수자는 모델 이름을 알고 있으므로 완전한 블라인드 평가는 아니다.
- 양쪽 **첫 응답끼리** 비교했다. Gemini 재시도·보충 후 최종 결과는 아래 별도 항목이다. 문구를 수정하거나 실패 문서를 교체하지 않았다.
- 통과 조건: 로컬 스키마·근거/페이지/필수 맥락 검사 + 별도 원문 대조에서 새 전제 없음·비중복. 문서에 나오는 사례를 설명하게 하는 것은 허용하되, 불확실한 본인 수행을 단정하거나 시각 자료만으로 개인의 과거 결정을 전제하면 탈락이다.

통과 질문 3개 이상을 확보한 문서는 Gemini 0/6, Luna 2/6이다. 생성한 모든 질문에 오류가 없으면서 3개 이상인 문서는 Luna d-naeon 1개뿐이다. 따라서 **Luna로 이름만 바꾸면 무인 MVP가 완성된다는 결과는 아니다.** 제외 판정은 모델 자동 검수의 성과가 아니라 이번 별도 Codex 평가다.

판정은 실제 거짓과 근거 계약 위반도 구별한다. 예를 들어 m-damyul의 게시물 제목은 실제 PDF에 있지만 선택 앵커에는 없어서 탈락했다. 이를 사실 환각으로 집계하지 않는다. 불확실한 참여/검증 여부는 먼저 확인하는 문장이 필요하다.

## 실제 토큰 기록

단위는 토큰. **Gemini는 첫 질문 API 호출**, **Luna는 이미지·파일 읽기와 도구/시스템 문맥을 포함한 전용 에이전트 세션 전체**다. 입력 규모나 시간을 순수 모델 효율의 직접 비교로 해석하면 안 된다. 원본 사용량 출처와 시각은 로컬 `report.json`에 보존했다.

Gemini 첫 호출 전체 토큰 합계는 응답의 `totalTokenCount` **50,074**다. m-jisun의 `thoughtsTokenCount`는 미제공이므로 추론을 임의로 0으로 채우지 않았다. 비용은 입력·전체 토큰을 포함한 실제 메타데이터로 계산할 수 있다.

Luna 전체 토큰은 **1,655,975**, 캐시 입력 **1,482,752**다. 추론을 제외한 출력 **11,560**은 실제 출력 카운터에서 실제 추론 카운터를 뺀 정확한 차이이며 토크나이저 추정이 아니다. 추론 16,943을 출력 28,503에 다시 더하지 않는다. 누적 `token_count` 스냅샷은 마지막 하나만 사용하고 여러 스냅샷을 합산하지 않는다. 모델 미확인·미완료·누락 카운터는 null로 남기는 회귀 테스트가 있다.

첫 Gemini 질문 호출은 문서별 **15.6~24.1초**. Luna 전용 세션은 **61.5~107.5초**다. 서로 다른 실행 범위이며 API 대 API 속도 비교가 아니다.

## Gemini 전체 워크플로우는 별도 보존

`mvp-23`은 결과 저장 6/6, 자동 질문 17개, 원문 검수 통과 5개다. 자동 `evidence_ready`는 2개지만 엄격한 참여·전제 기준에서는 완성 품질에 미달했다. 질문 개수 충족과 올바른 질문 생성은 다르다. 자세한 표는 [MVP_REPORT.md](MVP_REPORT.md).

공유 추출 문제도 남는다. m-vishv의 주요 성과 지표와 m-damyul의 측정 근거가 질문 입력에서 빠졌고, m-jisun/다미율의 연결 박스에 총 4개 경계 문제가 있었다. Luna 질문 작성만 바꿔서는 이 입력 결함이 해결되지 않는다. 또한 기존 재질문 차단 키가 변경된 질문 문장도 같은 과제로 처리해 d-asad의 유효한 수정을 막는 보수적 오탐을 발견했다. 이번 고정 실행을 소급 수정하지 않았다.

## 채택 판단과 저장 위치

다음 후보는 **Gemini 추출 유지 + Luna 질문 작성**이 합리적이다. 다만 실제 서비스용 API 실행에서 같은 입력으로 재검증하고, 참여 확인·근거 범위·수정/실험 전제 검사를 통과시킨 뒤 채택해야 한다. 이번 요청은 비교이므로 provider 기본값, 앱 경로, 자동 채택 설정은 바꾸지 않았다. 추가 유료 실험은 시작하지 않았다.
