## 현재 판단

**연구용 프로토타입이며 신뢰하고 배포할 MVP 품질은 아직 아니다.** 이번 시험은 Sonnet 질문 생성에 도달하지 않았으므로 새 조합의 질문 품질이나 기존 조합 대비 우위를 판정할 수 없다. 이전 완료 시험은 디자인 자동 9개/별도 적합 4개, 마케팅 자동 3개/별도 적합 2개였고 선정 핵심 포인트 누락 때문에 MVP 미달이었다.

- Astra가 26페이지 구조를 읽고 5·6·15·16페이지, 두 프로젝트, 세 포인트를 선정했다.
- 첫 프로젝트의 근거 4개를 추출했으며 Opus 검수는 2개를 허용했다. 콘셉트 원문과 제목은 정확한 크롭에 연결되어 있었다.
- 보류된 2개는 별도 원본 크롭에서 바구니 그림과 글자 크기 대비가 실제로 확인됐다. 앞선 독립 판독의 관찰 누락이 뒤 대조 단계에서 근거 부족으로 이어졌다. **정상 근거의 과잉 제외가 남아 있다.** 이 관찰을 자동 결과에 소급 반영하거나 근거를 재검수하지 않았다.
- Opus 판독은 관찰 항목 상한 8개 초과로 형식 재시도 1회 후 복구했다. Astra의 16페이지 영역 출력은 두 박스에서 상단이 하단보다 큰 좌표를 반환했다(`r16: [274,66,207,204]`, `r19: [573,153,207,301]`). 이 형식 재시도 도중 사용자 요청으로 중단됐다.
- Sonnet 호출 0회, 최종 질문 생성·질문 원문 대조·이번 웹 흐름 시험은 미실행이다. 생성 질문 수가 0인 것은 질문 모델 품질 0점이라는 뜻이 아니다.

검수자는 **Codex이며 사람 전문가가 아니다**. 원본 26페이지 연락시트, 선정 네 페이지의 2200px 원본 렌더, 첫 프로젝트의 정확한 연결 크롭 다섯 개를 별도 시각 확인했다. 모델 검수 결과 자체를 독립 정확도 증거로 삼지 않았다. 단일 개발 문서의 중간 결과이며 일반 모델 정확도 비교가 아니다.

## 구현·확인 범위

- 기존 Gemini 기본 경로는 그대로 유지했다. 명시적인 `src/trial.ts`에서만 Astra 분석 → Sonnet 검증 JSON 질문 → Opus 크롭 판독·검수 경로를 사용한다.
- PDF 조각은 기존 렌더러로 순서가 명시된 2200px PNG로 변환했고 Astra에 original detail을 전달했다. 세 모델은 JSON mode와 기존 로컬 Zod/의미 검사를 사용했다. 따라서 이전 native-PDF 경로와 완전히 통제된 모델만의 A/B 비교가 아니다.
- 이번 경로만 전체 모델 컨텍스트 대신 요청 텍스트 크기·이미지 치수에 따른 보수적 비용 여유를 사용했다. 이는 실측 토큰이 아니다. 실제 사용량/비용은 응답 값으로만 기록했다. ZDR·수집 금지·동일 모델 경로·출력 상한은 유지했다.
- 실행 전 타입 검사와 무과금 코어 **149/149** 통과. 새 의존성·운영 기본값 전환·웹 시험·커밋·푸시 없음.

다음 개선 우선순위는 모델 추가 교체보다 **정상 근거를 누락시키는 판독/검수 연결과 좌표 출력 안정성**이다. 다만 이번 중단 이후 수정이나 추가 유료 시험을 수행하지 않았다.
