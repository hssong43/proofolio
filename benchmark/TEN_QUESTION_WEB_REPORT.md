## 최신 결과: web-ten-04 / web-ten-05 — 기능은 부분 검증, 품질은 미달

사용자의 **$10 한도 재개 승인**에 따라 마케팅과 디자인을 각각 한 번 실제 웹 업로드했다. 마케팅은 스캔 중 상위 공급자 429로 실패했다. 호출 간격을 추가한 별도 디자인 실행은 **후보 13개(10+3) → 자동 최종 7개 → 별도 원문 검수 2개**다. 디자인 7개 합성 답변의 실제 로컬 저장은 통과했다. **두 문서의 최소 MVP 및 10문항 품질 목표는 달성하지 못했다.**

검수자는 Codex이며 사람 전문가가 아니다. 질문 본문·의도·각 가이드와 자기 연결 영역을 기준으로 판단했다. 질문을 수정하거나 결과 JSON에서 불합격 카드를 지워 자동 성과를 높이지 않았다. 마케팅 실패를 다른 문서로 교체하지 않았다.

### 실패 원인과 이번 조치

1. **공급 가용성:** 마케팅의 첫 네 PageIndex는 성공했고 다섯 번째는 HTTP 200 내부 `finish_reason=error`, `code=429`, `error_type=rate_limit_exceeded`였다. 공급자가 일시적인 upstream 제한이라고 명시했다. 앱 잔액 부족/인증 실패/질문 프롬프트 오류가 아니다. 과거 502와 동일 원인이라고 소급 단정하지 않는다. 같은 속도로 성공했던 과거 기록도 있어 정확한 RPM 한도는 미확인이다. [OpenRouter 오류 규격](https://openrouter.ai/docs/api_reference/errors-and-debugging).
2. **진단 정보 유실:** 이전 공용 HTTP 파서는 중첩 provider/code와 `X-Generation-Id`를 버렸다. 이번에는 안전한 코드·식별자만 보존하도록 수정했다. 원문/키를 포함할 수 있는 중첩 메시지는 저장하지 않는다. 과거에 버린 정보는 복구하지 못한다. [generation 식별자 헤더](https://openrouter.ai/docs/guides/features/response-caching).
3. **연속 호출 완화:** 공유 직렬 세션에서 유료 요청 시작 간격 16초를 추가했다. 비용 예약 전 대기·취소를 검사하며 HTTP 재시도나 공급자 fallback은 없다. 이후 디자인은 완료됐지만 한 번의 성공은 429 해결 증명이 아니다. 마케팅을 다시 업로드하지 않았다.
4. **질문 의미 검증:** `premise_checks`의 출처 문자열이 일치해도 그 시각 설명 자체가 틀리거나 전제 목록이 불완전하면 통과한다. q2의 크롭 밖 배경, q5의 축소/생략 과정이 실제 예다. 형식 강화만으로 모델의 의미 오판은 해결되지 않았다.
5. **커버리지/맥락:** 유학 가이드 추출 응답은 처음부터 `evidence: []`였다. 로컬 필터에 의한 제거가 아니고, 모델 내부 이유는 알 수 없다. 다른 후보 네 개는 필수 맥락 앵커를 빠뜨렸고, 두 개는 포스터를 focus 밖으로 보는 좁은 판정으로 제외됐다. 빈 추출 원인/필수 근거 묶음/선정 주제 해석이 다음 개선 대상이다.

### 이번 수정

- 독립된 수치 행 바로 다음에 지표명이 있는 대시보드는 완전한 값으로 인정한다. 저장된 실패 응답의 `1,014`가 로컬 검사를 통과하는 것을 확인했다. 부호·단위·수량 대상은 계속 보존하며 범위의 하한만 인용하는 오류도 회귀 검사로 막았다.
- 도시/성별/연령 등 분류 축을 분모로 채우지 않는다. 대표 분류 라벨은 로컬에서도 거절하고, 다른 의미 오류는 크롭 기반 검수로 확인한다. 분모 판별이 완전한 규칙 엔진은 아니다.
- 명확한 비텍스트 작업물은 글자 판독 불가만으로 제외하지 않는다. 불명확한 시각 객체나 판독 불가 텍스트 인용은 계속 제외한다.
- 근거 ID당 한 문항 및 같은 영역·분류 태그당 한 문항 제한을 제거했다. 같은 근거의 독립된 설명 과제는 허용하되 문장 중복, 의미상 같은 답, 반복 역할 확인은 제외한다. 최대 10문항·두 생성 라운드, 실패한 동일 과제 재검수 차단은 유지한다.
- 질문·의도·각 답변 가이드의 `premise_checks`에 전제별 앵커 순번·원문 구절을 요구하고 로컬에서 출처를 대조한다. 선택 이유를 열린 질문으로 묻는 것과 미기재 수정/문제 해결/제약을 실제 했다고 요구하는 것을 구분했다. 이 구조도 모델의 의미 오판을 완전히 막는 것은 아니며 별도 원문 검수를 대체하지 않는다.
